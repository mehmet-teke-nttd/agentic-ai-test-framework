# Security model

## Allowed capabilities

P0-P3 permits test metadata reads, allowlisted test execution, run-result/evidence inventory reads, deterministic analysis, and recommendations derived by a caller. It does not implement source edits, arbitrary file reads, raw commands, bug/work-item creation, commits, pushes, or pull requests.

## Trust boundaries and controls

- Agent input is an untrusted versioned contract.
- Project selection is an opaque ID mapped by the host; paths are never accepted from requests.
- The resolved project must remain beneath repository root.
- Filter values have length and character allowlists before becoming individual process arguments.
- `dotnet` is launched without a shell and every argument uses `ProcessStartInfo.ArgumentList`.
- Timeout has a configured upper bound; cancellation terminates the process tree.
- Run IDs are generated by the gateway and validated before lookup.
- Evidence lookups return an inventory scoped to one run. No endpoint returns arbitrary path contents.
- Structured errors avoid stack traces in the agent protocol.
- No credential, PAT, external URL, or Azure DevOps mutation is configured.

## Residual risks

Allowlisted test code itself executes with the host account's permissions. Operators should run the gateway using a least-privilege CI identity and review changes to allowlisted projects. Output and screenshots may contain application data in real deployments; set retention/access policies on the evidence root before connecting non-sample systems.

The gateway currently trusts the local `dotnet` resolved by the process environment. Production packaging should pin its runtime image and apply OS-level CPU, memory, filesystem, and network isolation.
